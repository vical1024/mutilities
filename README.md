# Mac 인터페이스 컨트롤러

macOS는 기본 키 설정으로 두고 이 앱 하나에서 단축키, 보조 키 교환, Finder 조작, 창 전환과 Hot Corner를 관리하는 SwiftUI 앱입니다. macOS 14 이상이 필요합니다.

## 메뉴 구성

- **입력 → 키보드**: Control/Command 교환, F1–F12, 한/영 입력 전환, Windows 스타일 Finder
- **입력 → 단축키**: 앱 표시/숨기기와 단일 동작 추가·편집
- **입력 → 매크로**: 실행 키와 여러 키 입력·대기 순서 편집
- **작업 공간 → 창 관리**: 창 전환과 창 배치. 조작 키는 펼쳐서 확인
- **작업 공간 → 핫 코너 / Dock / 디스플레이**: 모서리 동작, Dock 표시·크기·속도, 외장 모니터 연결 시 내장 화면 자동 끄기
- **관리 → 설정 점검**: 초기 설정·백업·복구, 권한, 충돌 검사
- **상단 톱니바퀴 → 앱 설정**: 별도 창에서 한국어/English 전환, 로그인 실행, 프로필 가져오기·내보내기. `⌘,` 또는 메뉴바의 앱 설정으로도 열 수 있음

표시 언어는 즉시 반영되고 다음 실행에도 유지됩니다. 입력 소스 전환과는 별개의 앱 표시 설정이며, 프로필과 시스템 백업을 변경하지 않습니다. 언어를 바꿔도 펼친 편집기·필터·입력 중인 값은 유지됩니다. macOS 파일 선택창 등의 시스템 제공 UI는 시스템 언어를 따릅니다.

고정 템플릿의 단축키와 활성 상태는 유지하며 창 배치는 정해진 순서로 표시합니다. 그룹에는 전체 사용 스위치 하나만 두고 개별 설정은 각 행에서 바꿉니다. 사용자 항목만 동작 변경·삭제가 가능합니다. 앱 표시/숨기기 항목은 기능명 아래 대상 앱을 표시하고, 편집기에서는 동작 → 대상 앱 → 키 조합 순서로 설정합니다.

디스플레이 자동 끄기는 스위치로만 켜고 끕니다. 복구 동작을 중복하는 일반 버튼은 제거했으며 실제 오류에서만 재시도가 나타납니다. 화면 제목·여백·설정 카드·단축키 표시는 공통 구성요소를 사용합니다. 상세 설명은 해당 설정의 도움말에 두고 오류와 복구 안내는 본문에 표시합니다.

## 자동 백업과 시점 복원

앱 시작 전 `History` 폴더에 관리 대상 macOS 설정과 앱 설정을 자동 백업하고 파일을 다시 읽어 검증합니다. 검증 전에는 엔진이나 Dock 설정을 적용하지 않습니다. 정상 종료에서는 엔진을 멈추고 시작 전 macOS 설정과 기능 키 모드를 복원한 뒤 종료합니다. 복원 실패 시 종료를 취소하고 백업을 유지합니다. 비정상 종료 시 복구 기록을 남기며 다음 시작에서 복원을 먼저 수행합니다. 기존 기능 키·화면 복구 보조 프로세스도 유지합니다.

완료된 시작·종료 회차 기준 최근 **15개 자동 백업**을 보관합니다. 진행 중인 회차, 수동 백업, 복원 직전 백업은 자동 삭제하지 않습니다. **설정 점검 → 초기 설정·백업·복구**에서 이름을 지정해 현재 시점을 저장하거나 과거 시점을 선택해 복원합니다. 명시적으로 시점 복원을 하면 그 시점이 현재 회차의 종료 복원 기준이 됩니다. 복원 직전 상태도 별도로 남깁니다.

시점 백업에는 키보드·Finder·창 크기·단축키·매크로·Hot Corner·Dock·Screen·로그인 실행 선택과 관리 대상 macOS 설정이 포함됩니다. 실제 창 위치, 이 앱과 무관한 macOS 설정, 개인정보 보호 권한은 포함하지 않습니다. 로그인 실행은 앱의 지속적인 선택이며 자동 종료 복원 대상이 아니고, 수동 시점 복원 시 변경합니다. macOS 승인이 필요한 경우 안내합니다. 화면 복원은 내장 화면을 켜는 안전 동작을 우선합니다.

Dock 설정은 적용 버튼 없이 변경 즉시 저장됩니다. 연속 조절 중에는 마지막 변경 후 0.2초에 최종 값만 자동 반영하며, 키보드 엔진을 다시 시작하지 않습니다. Dock 변경·검증·실패 복구는 Dock 설정만 읽고 씁니다. 엔진을 끄거나 앱을 종료하면 시작 전 macOS 값으로 복원합니다. macOS 기본값 유지는 권장 사항으로 제공하고 기본값 전환은 사용자가 실행합니다. 기본값이 아닌 시작 전 값도 그대로 백업·복원합니다. 시스템 보조 키 설정의 캐시로 인해 로그아웃·로그인이 필요할 수 있습니다.

백업 위치: `~/Library/Application Support/MacInterfaceController/History`. 예전 시스템 전용 백업은 `Backups`에 그대로 보관하며 이전 버전 복원 목록에서 접근합니다. 접근이 제한된 앱의 설정은 제외 목록으로 기록합니다.

## 처음 사용할 때

1. **설정 점검 → 충돌 검사**에서 다른 입력 앱을 확인하고 해당 앱의 메뉴에서 종료합니다. 단순 실행 감지, 조건부 규칙, 직접 중복을 구분해 표시합니다.
2. **설정 점검 → 초기 설정·백업 → 백업 후 macOS 기본값으로 전환**을 실행합니다.
3. 로그아웃하고 다시 로그인합니다. Command/Control이 원래 키로 동작하는 것을 확인한 후 **로그아웃 후 기본값 확인 완료**를 누릅니다.
4. **설정 점검 → 권한**에서 접근성·입력 모니터링을 허용하고, **키보드**에서 필요한 기능을 켭니다.
5. **앱 설정**에서 로그인 시 자동 실행을 켤 수 있습니다. 설정 창을 닫아도 메뉴바에서 계속 실행됩니다.

업데이트된 앱은 기존 앱 프로필을 유지하지만, 이 Mac의 초기 설정을 완료하기 전에는 보조 키 교환·Finder·창 전환·Hot Corner를 시작하지 않습니다. Shift+Space처럼 Command/Control이 없는 한/영 단축키는 초기 설정이나 리매핑 권한과 독립적으로 동작합니다. 기존에 지정한 Shift+Space 등의 조합은 그대로 가져옵니다. 새 설치의 기본 한/영 단축키는 Shift+Space입니다.

## 매핑 수명

- Command/Control 교환은 이벤트 탭에서만 처리합니다. 앱 실행 중 `hidutil`이나 macOS 설정에 매핑을 쓰지 않습니다.
- 설정 창 닫기: 모든 앱 매핑 유지.
- 엔진 끄기 또는 앱 완전 종료: 앱 단축키·교환·Finder 매핑·창 전환·Hot Corner 중단.
- 앱이 강제 종료돼도 이벤트 탭은 프로세스와 함께 사라지므로 이 앱의 보조 키 교환이 시스템에 남지 않습니다.
- 시작 전 관리 대상 macOS 설정은 종료 시 자동 복원합니다. 앱에서 지정한 동작 프로필은 다음 실행을 위해 유지합니다.
- 초기 설정 이후 다른 앱이 시스템 보조 키/HID 매핑을 다시 만들면 리매핑 엔진을 중지하고 알립니다. Command/Control을 사용하지 않는 한/영 단축키는 계속 사용할 수 있습니다.
- 실행에 필요한 보조 키/HID 검사는 전체 앱의 설정 목록 검사와 독립적으로 수행합니다. 전체 검사에서 디렉터리 응답이 늦어져도 창 전환 시작을 막지 않으며, 보조 키/HID 검사 자체가 실패하거나 매핑이 발견되면 리매핑은 계속 차단합니다.

## 백업과 기본값 전환

관리 대상은 현재 사용자의 다음 설정입니다.

- 전체 및 앱별 메뉴 단축키 (`NSUserKeyEquivalents`)
- macOS 기능 단축키 (`AppleSymbolicHotKeys`)
- Dock Hot Corner 값
- 일반 및 현재 기기 범위의 보조 키 매핑 (`com.apple.keyboard.modifiermapping.*`)
- `hidutil` 공통 `UserKeyMapping`

입력 소스, 키 반복 속도, 네트워크·보안 등 다른 설정은 변경하지 않습니다. 앱 고유의 자체 단축키 설정이나 별도 드라이버의 장치 전용 설정은 그 앱에서 해제해야 합니다.

백업은 `~/Library/Application Support/MacInterfaceController/Backups`에 저장합니다. 파일을 다시 읽어 검증한 뒤 변경하며, 부분 실패 시 기존 관리 대상 값을 복원하고 결과를 확인합니다. 복구도 실패하면 오류와 백업 복원 안내를 표시합니다. 작업 중 비정상 종료된 경우 엔진은 초기 설정 대기 상태이며 저장된 백업을 선택해 복구할 수 있습니다.

새 시스템 백업은 버전 5이며 Dock 크기·확대·표시 시간과 기능 키 환경설정을 포함합니다. 관리 대상 키와 접근 불가 도메인의 제외 목록을 보관합니다. 복원 시 제외 항목은 접근이 가능해졌더라도 덮어쓰지 않습니다. 기존 버전 2·3·4 JSON 백업도 읽으며, 그 백업에서 다루지 않던 Dock 속도·기능 키 설정은 지우지 않습니다. 복원 직전 상태도 백업합니다. 이전 버전의 전체 도메인 plist 백업은 보존하지만 새 UI에서는 JSON 백업만 복원합니다.

보조 키 설정은 macOS 로그인 세션에 캐시될 수 있어 초기 설정 후 로그아웃이 필요합니다. 앱은 실제 물리 키 동작을 자동으로 확인할 수 없으므로 사용자가 기본 동작을 확인한 뒤 엔진을 활성화합니다.

## 기능

- 전역 단축키 추가·삭제·개별 활성화 및 중복/등록 실패 안내
- 한/영 입력 소스를 직접 선택하며 마지막 입력기를 기억; 필요한 입력 소스가 없으면 안내
- 한/영 단축키의 적용 상태를 자동 표시하며, 오류가 발생하면 설정 점검으로 안내. 엔진을 끄거나 앱을 종료하면 한/영 단축키도 중지
- 좌우 Command/Control 교환
- Finder Enter 열기, F2 이름 변경, Forward Delete 휴지통 이동, Ctrl 기반 복사·이동 붙여넣기 등
- Finder 교환 후 Command+↑ 상위 폴더, Command+←/→ 이전·다음 폴더
- Finder 텍스트 편집 중에는 파일 탐색 매핑을 적용하지 않음
- 잘라내기 상태는 클립보드 변경, 붙여넣기, 엔진 재설정 시 해제
- 교환 후 Control+Tab으로 개별 창 세로 목록 (Control+Shift+Tab은 역순), ↑/↓ 선택, Enter 전환, Esc 취소
- 창 전환 목록의 **×** 또는 **W**로 해당 창의 닫기 버튼을 누릅니다. 전환 목록과 현재 앱은 유지하고, 실제 닫힘을 확인한 항목만 옆으로 사라지며 남은 항목이 이동합니다. 저장 확인이 필요하거나 닫기 실패 시 항목과 안내를 남깁니다. 해당 항목에서 Enter를 눌러 앱의 확인창을 처리할 수 있습니다. W를 길게 눌러도 한 번만 요청하며, 닫힘 확인은 요청한 창에만 최대 약 3초간 수행합니다. 마지막 창을 닫아도 빈 목록을 유지합니다. 선택 강조가 부드럽게 이동하고, Enter 또는 항목 클릭으로 창을 열 때 목록을 0.16초 동안 축소·페이드아웃합니다. macOS 동작 줄이기 설정을 존중합니다.
- 창 선택 시 숨김·최소화를 해제하고 선택한 창에 포커스를 지정합니다. 활성화 완료를 확인하며 실패하면 최대 3회 시도 후 창 전환 탭·메뉴바에 알립니다. 다른 앱으로 직접 이동하거나 새 창을 선택하면 이전 재시도는 취소합니다.
- 네 모서리 Hot Corner 및 다중 모니터 지원
- 15초 주기의 다른 입력 엔진/단축키 충돌 검사, 홈·메뉴바 알림과 종료·삭제 안내

충돌 검사는 알려진 실행 프로세스와 Karabiner 선택 프로필, 내부 예약 조합, 전역 단축키 등록 결과를 사용합니다. 다른 모든 앱의 비공개 설정을 완전히 분석하는 기능은 아닙니다. 다른 앱을 자동 종료하거나 삭제하지 않습니다.

## 창 배치

**창 관리 → 창 배치**에서 사용할 동작의 스위치를 켠 뒤 다른 앱의 창에서 사용합니다. 기존 초기 설정 완료 및 **설정 활성화**이 필요하며, 창 조작에는 접근성 권한이 필요합니다.

| 기본 단축키 | 동작 |
| --- | --- |
| Control + Option + ← / → | 현재 화면의 왼쪽 / 오른쪽 절반 |
| Control + Option + ↑ | 메뉴 막대·Dock을 제외한 영역으로 최대화 |
| Control + Option + ↓ | 이 기능으로 배치하기 전 위치·크기로 복원 |
| Control + Option + C | 크기를 유지하고 가운데 정렬 |
| Control + Option + Enter | 너비 유지 + 화면 높이 95% + 가운데 정렬 |

항목을 펼치면 키 조합과 높이 비율(30~100%)을 바꿀 수 있습니다. 기본값은 사용 가능한 화면 높이의 95%로, 위아래 여백은 각각 2.5%입니다. 화면보다 넓은 창은 화면 너비에 맞춥니다. 단축키와 비율은 자동 저장되며 프로필 가져오기·내보내기에 포함됩니다. 고정 항목은 창 관리에서 편집하며 사용자 추가 항목은 단축키에서 편집합니다.

창이 가장 많이 걸쳐 있는 모니터를 사용하며 위·왼쪽에 있는 모니터도 지원합니다. 연속 배치 후 복원하면 최초 배치 전으로 돌아가고, 직접 이동·크기 변경한 뒤 배치하면 그 위치를 새 복원 기준으로 삼습니다. 복원 기록은 앱 실행 중 최근 64개 창에 한정되며, 모니터를 분리했다면 현재 연결된 화면 안으로 복원합니다. 전체 화면 및 위치·크기 변경을 지원하지 않는 창은 오류를 표시합니다. 앱의 최소 크기 제한 때문에 절반 크기 등에 맞지 않을 수 있으며 이 경우 창 배치 화면·메뉴바에서 확인할 수 있습니다.

## 기능 키 · 특수 기능 키

**키보드 → 입력 및 키 동작**에서 F1~F12 기본 동작을 전환합니다. 켜면 표준 F1~F12, 끄면 밝기·음량 등 키에 표시된 특수 기능이 우선입니다. Fn(🌐)을 함께 누르면 반대 동작을 사용합니다.

앱이 실행 중이고 **설정 활성화**이 켜져 있을 때만 적용합니다. 앱 종료·엔진 끄기·**설정 활성화 끄기**으로 적용 전 동작을 복원합니다. 별도 복원 프로세스가 앱의 강제 종료도 감지합니다. macOS의 저장된 기능 키 환경설정은 변경하지 않으며, 적용 후 다른 곳에서 모드를 바꿨다면 종료 시 그 변경을 보존합니다. 설정 창을 닫는 것만으로는 복원하지 않습니다.

기존 프로필은 기능 키 모드를 지정하지 않은 상태로 가져와 원래 동작을 유지합니다. 선택한 모드는 프로필에 저장되어 다음 실행과 다른 Mac에서도 적용됩니다. 실제 적용 상태·오류·재시도는 같은 화면에서 확인할 수 있습니다. 초기 설정 완료 여부와 독립적으로 사용할 수 있지만, 키보드 자체 Fn Lock이나 제조사별 기능 키 제어는 지원하지 않을 수 있습니다.

## 내장 화면 자동 끄기·복구

**디스플레이 → 외장 모니터 연결 시 내장 화면 끄기**를 켭니다. 처음에는 꺼져 있으며, 이 Mac에만 저장되고 키보드 프로필 가져오기·내보내기에는 포함되지 않습니다. **설정 활성화**이 켜져 있으면 키보드 초기 설정·접근성 권한과 독립적으로 동작합니다.

- 활성 외장 화면이 2초 동안 안정적으로 감지되면 내장 화면을 끕니다. 단순 밝기 조절이 아니라 화면 구성을 비활성화합니다.
- 마지막 외장 화면을 분리하면 보조 프로세스가 최대 약 0.25초 주기로 감지하고 내장을 켭니다. 실제 점등에는 macOS의 화면 전환 시간이 추가됩니다.
- 자동 전환/엔진 끄기, 메뉴바·디스플레이 설정의 **자동 끄기 스위치 해제**, 앱 정상 종료 시 내장을 켭니다. 설정 창만 닫으면 계속 실행합니다.
- `DisplayGuard`가 화면 변경을 소유하며 앱의 전용 파이프를 감시합니다. 앱 크래시·강제 종료 시 EOF로 복구하고, 앱이 멈추면 마지막 생존 신호 후 약 8초에 복구합니다.
- 보조 프로세스가 실패하면 앱도 복구를 시도하고 자동 끄기를 중지합니다. 보조 프로세스의 응답이 끊기면 종료시킵니다. 실패 후에는 **다시 시도** 또는 자동 전환을 껐다 켜야 합니다.
- 화면 변경에는 `CGConfigureOption.forAppOnly`만 사용합니다. 보조 프로세스까지 강제 종료되면 macOS가 현재 로그인 세션의 화면 구성으로 되돌리는 것을 추가 안전장치로 사용합니다. 화면 꺼짐을 시스템 환경설정에 저장하지 않습니다.
- 지원 여부·활성 화면 목록·변경 결과를 확인하며, 확인에 실패하면 내장 켜기를 시도하고 중지합니다. 중복 앱 실행 시 화면을 제어하는 보조 프로세스는 하나만 허용합니다.

`SLSConfigureDisplayEnabled`라는 macOS 비공개 API를 런타임에 확인해 사용합니다. 운영체제 업데이트, WindowServer 장애, 하드웨어 장애, 다른 디스플레이 앱의 개입까지 포함한 **무조건 복구는 보장할 수 없습니다**. 내장 화면이 켜진 상태에서만 시작할 수 있으며 덮개를 연 MacBook용입니다. macOS가 활성 외장 화면으로 보고하는 화면을 기준으로 하므로 가상 화면/원격 화면을 함께 사용하는 구성은 실제 케이블 연결과 동일하게 취급될 수 있습니다.

설계 근거: [Apple의 화면 구성 변경 수명](https://developer.apple.com/documentation/coregraphics/cgconfigureoption), [비공개 API의 함수 시그니처 참고](https://github.com/calvincchan/displaytoggle). 구현은 영구 변경 대신 앱 수명에 한정하고 별도 생존 감시·결과 확인을 추가합니다.

검증: `swift test`는 외장 없음, 안정화/연결 흔들림, 여러 외장 중 마지막 분리, 변경 중 분리, 부분 실패, 감시 신호 중단, 복구 실패와 재시도를 모의 장치로 검증합니다. 실제 화면이 꺼진 상태에서 케이블 분리·앱/보조 프로세스 강제 종료·잠자기/깨우기는 외장 연결 상태에서 별도 확인해야 합니다.

외장/가상 화면을 모두 해제한 상태에서 `python3 Tools/DisplayGuardSmokeTest.py`로 실제 보조 프로세스의 EOF, SIGTERM, 중복 실행 차단, 생존 신호 타임아웃, 잘못된 신호, 부모 SIGKILL에 따른 EOF 복구 경로를 검사할 수 있습니다 (`swift build` 후 실행). 이 검사는 내장이 켜진 상태를 유지하므로 실제 점등 복구의 검증을 대신하지 않습니다.

## 단축키로 키 연속입력 매크로 실행

**단축키 → 단축키 추가 → 매크로 추가**를 선택합니다. 실행할 단축키를 지정하고 키 입력과 대기 단계를 추가한 뒤 활성화하세요. 단계별 키·보조 키·대기 시간(ms)을 지정하고 순서를 바꾸거나 삭제할 수 있습니다. 일반 문자 키, 숫자, Enter·Tab·Esc·방향키·F1~F12 등을 지원합니다.

예: `⌃⌥K`에 `⌘C → 300ms 대기 → Tab → ⌘V`를 지정할 수 있습니다. 매크로의 보조 키는 대상 앱에 전달할 macOS 키 기준이므로, Command/Control 교환을 켜도 복사는 `⌘C`로 지정합니다.

- 단축키와 보조 키에서 손을 떼면 현재 앞에 있는 앱에서 순서대로 한 번 실행합니다.
- **Esc**, 메뉴바의 **매크로 중지**, 엔진 끄기로 중단합니다. 다른 앱으로 이동하면 남은 입력을 중단합니다.
- 실행 중 자체 전역 단축키를 해제하고 종료 후 다시 등록해 재귀 호출을 막습니다. 입력 이벤트에는 표식을 붙여 Command/Control이나 Finder 매핑을 두 번 적용하지 않습니다.
- 최대 100단계, 단계당 대기 0~5초, 대기 합계 30초입니다. 실제 앱의 반응이 느리면 단계별 대기를 늘려 주세요.
- 매크로 실행에는 이 Mac의 초기 설정 완료와 접근성·입력 모니터링 권한이 필요합니다.
- 프로필 내보내기에는 매크로도 포함합니다. 새 내보내기 형식은 버전 3이며 기존 버전 1·2 프로필도 가져올 수 있습니다.

## 다른 Mac으로 설정 이동

**앱 설정**에서 JSON 프로필을 내보내고 가져옵니다. 단축키, Hot Corner, Command/Control 교환, Finder 모드, 창 전환과 기능 키 기본 동작 설정을 포함합니다. 가져오기 전에 현재 앱 프로필을 `Application Support/MacInterfaceController/Profiles`에 보관합니다.

시스템 백업, 이 Mac의 초기 설정 완료 상태, 권한, 로그인 자동 실행, 입력 소스 ID는 이동하지 않습니다. 새 Mac에서도 먼저 초기 설정을 완료해야 합니다. 지원하지 않는 버전, 중복 활성 단축키, 빠진 코너 등 잘못된 설정 파일은 적용 전에 거부합니다.

## 시스템 검사 호환성

- `hidutil`의 기존 단일 값과 macOS의 장치별 표 출력을 모두 읽습니다. 장치별 매핑이 서로 다르면 공통 백업으로 합치지 않고 변경 전에 안내합니다.
- 전체 환경설정 도메인을 순회하는 대신 로컬 사용자 설정 파일에서 메뉴 단축키가 있는 앱을 찾고, 그 앱과 관리 대상 시스템 키만 조회합니다. 별도 컨테이너·다른 사용자의 설정은 검사 범위에 포함하지 않습니다.
- 읽지 못한 다른 앱의 로컬 설정 파일은 점검 화면과 백업의 제외 목록에 기록하고 그대로 둡니다. 읽기·백업 검증이 된 범위만 초기화하며, 보조 키/HID 등 필수 검사가 실패하면 계속 차단합니다. 전체 디스크 접근 권한을 초기 설정의 필수 조건으로 두지 않습니다.
- 백업 준비 실패 시 기존 초기 설정 상태를 복구합니다. 상태 진단에는 갱신 시각·권한·시스템 검사 오류·최근 창 전환 오류가 포함됩니다.

## 빌드 및 검증

```bash
swift test
./scripts/build-app.sh
open "dist/Mac Interface Controller.app"
```

빌드는 기능 키 복원 도우미 `FunctionKeyRestore`도 앱 번들에 포함하고 서명합니다.

실행 중인 앱이 있을 때 빌드는 별도 스테이징 번들을 검증한 뒤 교체합니다. 실행 중 프로세스는 자동 종료하지 않으므로 새 버전을 사용하려면 기존 앱을 완전히 종료한 뒤 다시 여세요.

로그인 자동 실행은 빌드된 `.app`에서 설정합니다. macOS가 승인을 요구하면 로그인 항목 설정으로 안내합니다. 개발자 인증서가 있다면 `CODE_SIGN_IDENTITY="인증서 이름" ./scripts/build-app.sh`로 서명할 수 있습니다. 로컬 ad-hoc 빌드는 접근성 권한을 다시 요구할 수 있습니다.

시스템 상태만 읽고 변경하지 않는 진단:

```bash
swiftc Sources/MacInterfaceController/SystemDefaultsService.swift Sources/MacInterfaceController/HIDMappingParser.swift Sources/MacInterfaceController/MenuShortcutDiscovery.swift Tools/SystemSettingsInspect.swift -o /tmp/mac-controller-inspect
/tmp/mac-controller-inspect
```

실제 입력 소스를 왕복 전환한 뒤 원래 상태로 되돌리는 수동 점검:

```bash
swiftc Sources/MacInterfaceController/InputSourceManager.swift Tools/InputSourceSmokeTest.swift -framework Carbon -o /tmp/input-source-smoke-test
/tmp/input-source-smoke-test
```

자동 테스트는 임시 메모리 저장소에서 백업 실패/부분 변경/복구를 검증하고, 프로필 유효성 검사와 실제로 전송하지 않는 CGEvent의 키 변환을 검사합니다. 사용자 Mac의 키 설정을 초기화하거나 실제 파일을 이동하지 않습니다. 로그인 자동 실행, 로그아웃 후 시스템 반영, 다른 앱에서의 실제 입력은 권한을 허용한 앱으로 수동 검증해야 합니다.

일반 설정 화면에는 테스트·수동 상태 갱신 버튼을 두지 않습니다. 권한·기능 키·등록 상태는 자동 갱신하고, 앱으로 돌아오면 시스템 설정과 충돌 검사를 갱신합니다. 실제 오류에서의 복구·재시도와 기본값 확인 완료는 유지합니다.

Dock 크기는 아이콘 크기 기준입니다. 저장된 크기를 읽어 표시하며 지정값이 없으면 ‘기본값’으로 표시합니다. 예전 속도 전용 설정과 백업은 Dock 크기를 덮어쓰지 않습니다.

Dock 표시 방식은 상시 표시 / 자동 숨기기 중 선택합니다. 자동 숨기기일 때 현재 Dock 위치(왼쪽·하단·오른쪽 가장자리)를 화면 예시로 표시하며, 지연·펼침 시간을 설정할 수 있습니다. 예시는 위치 안내이며 감지 영역을 임의로 제한하지 않습니다.

모든 단축키는 Control·Command 교환 후의 macOS 키 기능을 기준으로 합니다. 교환 시 표시된 ⌃는 물리 Command, ⌘는 물리 Control을 누릅니다. 창 전환, Finder 조합, 한/영, 창 배치, 사용자 단축키 및 매크로 트리거에 동일하게 적용합니다. 매크로가 생성하는 키 입력도 표시된 macOS 기능 그대로 전달하며 다시 교환하지 않습니다.

## 백그라운드 부하

화면 자동 전환이 꺼져 있으면 0.5초 타이머를 실행하지 않고 macOS 화면 변경 알림으로 상태를 갱신합니다. 화면 복구 보조 프로세스가 실행·종료 처리 중일 때는 기존 0.5초 생존 확인을 유지합니다. 전체 설정 파일 검사는 시작·앱 활성화·명시적인 점검 시 수행하며 매분 반복하지 않습니다. 키 매핑 안전 검사와 충돌 검사는 기존 15초 주기를 유지합니다. 값이 같은 권한·화면·기능 키 상태는 UI에 반복 발행하지 않습니다.

### 앱 표시 / 숨기기

단축키 → 단축키 추가 → **앱 표시 / 숨기기 추가**에서 원하는 앱과 단축키를 설정합니다. **대상 앱** 메뉴에서 실행 중인 앱을 선택하거나 **다른 앱 선택…**으로 앱 파일을 고른 뒤 스위치를 켜세요. 새 항목의 기본 키는 `⌘ + ⇧ + '`이며 원하는 조합으로 변경할 수 있습니다. 여러 항목을 추가해 앱마다 다른 키를 지정할 수 있습니다.

단축키를 누르면 선택한 앱을 실행하거나 앞으로 가져오고, 대상 앱이 전면에 있을 때 다시 누르면 앱을 숨겨 직전에 사용하던 앱으로 돌아갑니다. 앱의 창과 실행 중인 작업은 유지되며, 창이 여러 개라면 앱 전체에 적용됩니다. 다른 창의 위치나 크기는 변경하지 않습니다.

기존 터미널 전용 단축키는 터미널이 선택된 일반 앱 항목으로 이어집니다. 해당 항목을 펼쳐 다른 앱으로 변경할 수 있습니다. Raycast 등에서 같은 단축키를 사용 중이면 해당 등록을 해제한 후 이 앱에서 활성화하세요.

### UI 검증 (2026-10)

한국어·영어 8개 주요 화면을 동일한 SwiftUI 코드로 렌더링해 확인했습니다. 검증 이미지는 로컬 `Diagnostics` 폴더에 보관하며 저장소에는 포함하지 않습니다. 렌더링은 서비스가 시작되지 않는 별도 메모리 설정을 사용하며 실제 화면 자동 끄기나 키 매핑을 변경하지 않습니다.

현재 설치된 Command Line Tools에서 기본 macOS 27 SDK의 SwiftUI 매크로와 Swift Testing 플러그인 검색 문제가 있으면 다음과 같이 설치된 26.5 SDK와 테스트 플러그인 경로를 지정할 수 있습니다.

```bash
swift test --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk -Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing
SWIFT_SDK_PATH=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk ./scripts/build-app.sh
```


### 단축키와 매크로 (0.7.1)

사이드바의 단축키는 앱 표시/숨기기와 단일 동작, 매크로는 여러 키 입력과 대기 순서를 관리합니다. 기존 설정은 자동으로 해당 화면에 표시되며 두 화면의 실행 키 충돌은 함께 검사합니다.

매크로 추가를 누르면 새 편집 항목으로 이동합니다. 이름, 실행 키, 입력 순서를 지정한 뒤 스위치를 켜세요. 유효한 키 입력이 없는 새 매크로는 켤 수 없으며, 실행 중 Esc 또는 매크로 중지 버튼으로 중단할 수 있습니다. 기존 이름 없는 매크로와 프로필도 그대로 사용할 수 있습니다.

화면 제목, 그룹 제목, 메뉴와 설정 라벨은 일반 굵기로 통일했습니다. 크기·여백·색상으로 정보의 구분을 유지합니다.


### 보조 문구 정리 (0.7.2)

Finder와 창 배치의 전체/일부 활성화 상태 및 사용 개수, 창 전환의 물리 실행 키 설명을 제거했습니다. 단축키·매크로 페이지의 소개 문장, 추가 방법 안내, 매크로 단계 수·전체 대기 시간 요약도 제거했습니다. 상태는 스위치와 개별 설정에서 직접 확인합니다. 입력 오류와 실행 실패처럼 조치가 필요한 안내는 해당 위치에서 표시합니다.


## GitHub Actions 빌드와 Release

[Build and release macOS app](.github/workflows/build-and-release.yml)은 `main` 푸시와 Pull Request에서 테스트·빌드·패키징을 수행합니다. Actions 화면의 Run workflow로 수동 검증도 가능합니다. 빌드 결과는 실행 화면의 Artifacts에 14일간 보관합니다.

`vMAJOR.MINOR.PATCH` 태그를 푸시하면 테스트가 성공한 Apple Silicon용 ZIP과 SHA-256 체크섬을 [GitHub Releases](https://github.com/vical1024/mutilities/releases)에 자동 게시합니다.

| 파일 이름 끝부분 | 대상 |
| --- | --- |
| `macos-arm64.zip` | Apple Silicon Mac (M1 이상) |
| `.zip.sha256` | 해당 ZIP의 SHA-256 체크섬 |

자동 배포는 Apple Silicon(M1 이상), macOS 14 이상용입니다. ARM64 macOS 15 러너에서 Xcode 16.4로 테스트하며 Intel용 산출물은 만들지 않습니다. 앱과 복구 보조 프로그램을 함께 서명하고, ZIP을 다시 풀어 서명·실행 권한을 검사한 뒤 게시합니다. 인증서를 별도로 지정하지 않은 자동 빌드는 ad-hoc 서명이며 Apple 공증은 포함하지 않습니다. 다운로드한 앱의 첫 실행에서 macOS의 개인정보 보호 및 보안 승인이 필요할 수 있습니다.

### 버전 배포

1. `Resources/Info.plist`의 `CFBundleShortVersionString`을 배포 버전으로, `CFBundleVersion`을 증가한 빌드 번호로 변경합니다.
2. 변경사항을 커밋하고 `main`에 푸시합니다.
3. 앱 버전과 일치하는 태그를 푸시합니다. 현재 버전의 첫 배포 예:

```bash
git tag -a v0.7.2 -m "Release v0.7.2"
git push origin v0.7.2
```

태그와 앱 버전이 다르거나 태그 형식이 잘못되면 게시 전에 실패합니다. 브랜치 푸시·Pull Request·수동 실행에서는 Release를 게시하지 않습니다. 실패한 태그 실행은 Actions에서 재실행하면 되며, 미완료 초안은 이어서 업로드합니다. 이미 게시한 Release는 자동으로 덮어쓰지 않으므로 새 버전 태그를 사용하세요.

별도 GitHub 토큰을 등록할 필요는 없습니다. 빌드 작업은 읽기 권한만 사용하고, 태그의 Release 작업에만 기본 `GITHUB_TOKEN`의 `contents: write` 권한을 부여합니다. 사용하는 외부 Actions는 커밋 SHA로 고정합니다.

### 로컬 배포 파일 만들기

```bash
./scripts/package-release.sh v0.7.2
```

현재 Mac의 아키텍처용 ZIP과 체크섬을 `dist/releases/`에 만듭니다. `dist`의 기존 앱은 교체하지 않습니다. 필요하면 기존 빌드와 동일하게 `SWIFT_SDK_PATH` 또는 `CODE_SIGN_IDENTITY`를 지정할 수 있습니다. `BUILD_OUTPUT_DIR`은 일반 앱 빌드의 출력 폴더, `PACKAGE_OUTPUT_DIR`은 배포 ZIP의 출력 폴더를 바꿉니다.
